## 1. Flagship vendors

Note: Gartner formally relabeled this market. Its 2026 listing reads "Project and Portfolio Management (Transitioning to Strategic Portfolio Management)," and the standalone Magic Quadrant is now titled Strategic Portfolio Management (SPM). The same vendors anchor both the legacy PPM frame and the current SPM frame.

1. Broadcom Clarity (formerly CA PPM, originally Niku Clarity). Named a Leader in the 2025 Gartner Magic Quadrant for SPM (second consecutive year). Part of Broadcom's ValueOps platform. Owner: Broadcom.
2. Planview (Planview Portfolios, formerly Enterprise One / Innotas heritage). The volume leader for enterprise PMO / EPMO portfolio planning. In February 2025 Planview acquired Sciforma, consolidating two of the historical PPM specialists under one roof. Owner: Planview (PE-backed, TPG / TA Associates).
3. ServiceNow SPM (formerly ServiceNow ITBM / PPM). Strong where portfolio management rides on an existing ServiceNow ITSM / platform footprint. Owner: ServiceNow.
4. Planisware (Planisware Enterprise / Orchestra). Specialist for R&D-, engineering-, and new-product-development-driven portfolios with complex stage-gate pipelines (pharma, aerospace, industrial). Owner: Planisware (publicly listed on Euronext Paris since 2024).
5. Microsoft (Project for the web / Planner / Project Online). Broad-reach incumbent; Gartner lists Microsoft in the transitioning PPM-to-SPM market. Owner: Microsoft.

Adjacent / collaborative-work-management names that show up in PPM shortlists (Adobe Workfront, Smartsheet, monday.com, Asana) compete at the lighter end but are primarily classified in collaborative work management, not enterprise SPM.

## 2. Entity x vendor surface matrix

Core = nearly every PPM/SPM vendor models it. Common = most do. Specialist = only some (often the R&D / financial-heavy tools).

| Entity / data object | Classification | Notes |
|---|---|---|
| Projects | Core | The base unit of execution across all vendors. |
| Portfolios | Core | Grouping / governance container; defines the market. |
| Resources (people, roles, capacity) | Core | Resource and capacity management is a defining engine. |
| Demand / intake requests (ideas, proposals) | Core | Demand-and-idea management is a named PPM capability. |
| Programs | Common | Mid-tier grouping between portfolio and project. |
| Tasks / schedules / Gantt | Common | Present everywhere, but the scheduling depth varies. |
| Timesheets / time tracking | Common | Strong in Clarity, Planview, Sciforma; lighter in MS Planner. |
| Financial plans / budgets / cost plans | Common | Clarity and Planisware are financial-heavy; lighter tools thinner. |
| Scenarios / what-if / capacity planning | Specialist | The non-trivial optimization engine; deep in Planview, Clarity, Planisware. |
| Roadmaps / strategic outcomes / OKRs | Specialist | The "strategic" overlay that pushed PPM toward SPM. |
| Stage gates / phase-gate pipelines | Specialist | Planisware and Sciforma for R&D / NPD portfolios. |
| Benefits realization / value streams | Specialist | Broadcom ValueOps; Planview value-stream tie-in. |

This is exactly the entity set SPM already claims (demand, project, resource, outcome records, plus the scenario / capacity / roadmap engines).

## 3. Required compliance entities

None / minimal. PPM/SPM is an internal management-and-governance market. It carries no externally mandated compliance entity set (no statutory filing object, no regulated audit artifact, no certification-bearing record) the way payroll, GxP, or financial-reporting domains do. Governance / approval / audit-trail features exist, but they are general workflow controls, not a domain-specific regulated compliance entity. certification_required = false. Stated explicitly: there are no required compliance entities for this market.

## 4. Modularization hypothesis

If this market were ever promoted on its own (it should not be; see verdict), it would split into roughly four modules, which are the same modules SPM already implies:

- Demand and Intake: ideas, proposals, intake requests, scoring / prioritization criteria, business cases.
- Portfolio Planning: portfolios, programs, investment categories, scenarios, what-if capacity models, roadmaps, strategic outcomes / OKRs.
- Execution and Scheduling: projects, tasks, schedules / Gantt, milestones, dependencies, stage gates.
- Resource and Financials: resources, roles, capacity, allocations, timesheets, cost plans / budgets, benefits realization.

Every one of these modules maps cleanly onto SPM's existing surface, which is the core reason PPM is not a separate domain.

## 5. Point-solution-market test

Can you name >= 3 INDEPENDENT vendors whose FLAGSHIP product is this market? Yes.

- Broadcom Clarity is a dedicated PPM/SPM product line.
- Planview's flagship is portfolio management (and it now owns former rival Sciforma).
- Planisware is a pure-play portfolio-management vendor (publicly listed, single-market focus).

So the market passes the point-solution test on its own merits. PASSING THIS TEST CONFIRMS IT IS A REAL MARKET, but it does not make PPM a *distinct* market from SPM: every one of these flagship vendors is evaluated by Gartner inside the single SPM Magic Quadrant. The point solutions are the same point solutions that anchor the existing SPM domain.

## 6. Overlap analysis vs the existing catalog (especially SPM)

PPM is not a distinct market from SPM. It is the prior name of the same market.

- Gartner retired the standalone "Project and Portfolio Management" Magic Quadrant and now publishes "Strategic Portfolio Management," explicitly tagging its market page "Project and Portfolio Management (Transitioning to Strategic Portfolio Management)."
- The flagship vendor set is identical: Broadcom Clarity, Planview, ServiceNow, Planisware, Microsoft appear in both frames.
- The catalog's SPM entity surface (demand, project, resource, outcome records; resource allocation, capacity what-if, roadmap scenario modeling) already covers every PPM Core and Common entity in section 2.
- No gap exists that SPM does not already hold. PORT-MONIT (private-capital fund monitoring) and APM (application portfolio rationalization) are unrelated despite name overlap.

Conclusion: PPM is already covered by SPM. It is a naming / vintage difference, not a market boundary.

## 7. Triage recommendation

VERDICT: already-exists:SPM

Rationale: PPM and SPM are the same enterprise market under two names; Gartner formally renamed "Project and Portfolio Management" to "Strategic Portfolio Management," and the flagship vendors (Broadcom Clarity, Planview, Planisware) are evaluated in the single SPM Magic Quadrant. The live catalog already carries SPM with the exact entity surface PPM would claim (demand, project, resource, outcome records, plus the capacity / scenario / roadmap engines), so promoting a separate PPM domain would duplicate SPM, not extend coverage. No new domain_code is proposed. The only optional, non-blocking action is to record "PPM" and "Project and Portfolio Management" as synonyms / aliases of SPM so future intake requests resolve to the right domain, and optionally to note the Planview-Sciforma (Feb 2025) consolidation against SPM vendor coverage.

Because the verdict is already-exists, no promotion metadata (domain_code, description, or the 7 business-metadata estimates) is proposed.
