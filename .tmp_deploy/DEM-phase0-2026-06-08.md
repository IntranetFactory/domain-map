## Framing analyst signals (decide the boundaries)

- **Gartner runs TWO separate 2025 Magic Quadrants here.** "Digital Experience Monitoring" (DEM)
  and "Digital Employee Experience Management Tools" (DEX) are distinct markets, not one. Gartner
  defines DEM as measuring availability, performance, and quality of the UX of critical applications
  for internal users (employees, contractors), external users (customers, partners), or a digital
  agent connecting to an API. Gartner defines DEX as measuring employee sentiment toward and
  performance of company-provided technology, surfacing insights, self-healing automation, and
  support optimization from aggregated endpoint + application + sentiment + organizational data.
  DEM is app/service/API-centric across all user types; DEX is employee-centric with sentiment and
  org context. The DEM leaders (Dynatrace, New Relic, Catchpoint, ManageEngine, SolarWinds) and the
  DEX leaders (Nexthink, ControlUp, Riverbed Aternity Employee Experience) are largely different
  vendors. This is the decisive evidence for the DEX-boundary question.
- **The contested surface is split three ways across DEM / OBS / NPMD.** DEM masters synthetic +
  RUM + experience scoring + friction/anomaly. NPMD (id 82, also under ITOM) owns network-path
  instrumentation, hop-by-hop path, and BGP as its own market; DEM consumes the path signal. OBS
  (id 7) aggregates metrics/logs/traces/availability series; DEM publishes synthetic results into
  OBS but masters its own data plane. APM (the runtime kind: Datadog/Dynatrace/New Relic APM tier,
  AppDynamics) owns app-internal traces and is distinct from the catalog's existing APM code
  (Application Portfolio Management, id 10, LeanIX/Ardoq).

## Compliance entities (non-optional for regulated scope)

DEM is not a statutory market (no FCRA/HIPAA/SOX/PCI compliance entity is structurally required).
The one genuine regulatory hook is privacy: RUM and per-user friction telemetry capture identifiable
end-user usage, so GDPR / CCPA-CPRA apply to those masters. This is expressed via the
`has_personal_content` pattern flag (Rule #12) on real_user_sessions, digital_friction_events, and
endpoint_experience_scores, plus optional `domain_regulations` tags for GDPR / CCPA. No
statute-prefixed master entities. Session replay raises the same privacy surface and would inherit
the flag if loaded.

## Modularization hypothesis

Two full modules cover the DEM data plane cleanly:

- **DEM-WEB-EXPERIENCE** masters the synthetic + RUM web surface: synthetic_monitoring_results,
  synthetic_monitors, monitoring_locations, real_user_sessions, page_load_events, web_vitals,
  session_replays, sla_compliance_records. This is the Datadog RUM+Synthetic / Dynatrace DEM /
  New Relic / Catchpoint web-and-synthetic pillar.
- **DEM-ENDPOINT-EXPERIENCE** masters the device-side scoring + anomaly surface:
  endpoint_experience_scores (computed), endpoint_anomaly_findings (workflow), digital_friction_events.
  This is the Catchpoint DEX-Sonar / ThousandEyes endpoint-agent pillar (the DEM-flavored slice, with
  the sentiment + device-health + self-healing slice carved out to DEX-PLATFORM).

`performance_baselines` is shared infrastructure (smart baselines feed both modules); model it as
master in one module and embedded_master/consumer in the other if it lands.

A third module (DEM-SAAS-REACHABILITY) only pays off once sla_compliance_records and the SaaS-uptime
surface are first-class; today it would carry a single master. Recommend deferring it.

Boundary decisions (each grounded above):
- `network_path_hops` / BGP -> CONSUMED from NPMD (id 82). NPMD is the network-path market.
- `application_response_traces` -> CONSUMED from a new APM-MONITORING domain (distinct from the
  catalog's APM = Application Portfolio Management). Datadog/Dynatrace/New Relic/AppDynamics own it.
- `device_health_summaries`, `employee_sentiment_responses`, `remediation_actions` -> belong to a
  DEX-PLATFORM domain (Nexthink / ControlUp / Aternity Employee Experience), separate Gartner MQ.
